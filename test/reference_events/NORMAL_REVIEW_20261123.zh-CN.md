# Normal瓶颈证据复盘与下一轮大区间对照

日期：2026-11-23。覆盖仓库早期复测、模式对齐、阶段观测、FIFO干预、串行/并发微基准、fence及CQE实验，最新上传结果为49fd92a6；CQE构建修复为89340831。

本次先确认大方向，不将“FADD返回后约351 μs”等同剩余全部性能差距。已有证据较强地指向历史204→202方向的持续推进长尾，但最新tail-off下是否仍以该方向为主、差距主要积累在命令读取前、提交后还是接收消费中，尚缺同点的双后端记录。下一轮优先补这一缺口，不先运行CQE专项，不追加LL、tokens扫描、队列深度矩阵或fence矩阵。

## 1. 计时口径先分开

- 历史连续调用、paced逐次同步、带探针微基准分别归档。CPU/GPU版本、生产源码、内核、设备及构建不能混用。
- 完整API、GPU跨角色包络、单请求跨度、SDK调用CPU时间是不同指标。独立中位数不相加，并行请求等待不累计到整体。
- max_local是同序号两端本地API耗时的较大者，不是统一跨机时钟下的makespan。不能跨机相减时间戳。
- RDMA和URMA使用各自适用的内核。对比两套实际栈，不能把全部差异归给某行URMA代码。
- 下文“历史匹配组”指两端源码、负载、计时和已记录运行库尽量匹配的一组；不表示消除了内核、设备及SDK差异。

## 5. 候选排序及缺失的证据

1. **持续负载下的推进/排队长尾，优先204→202。** 有整体方向、GPU大包络、大WRITE尾部、第6块集中及背压重放共同支持。它是宽范围候选，尚不能等同CPU、设备或网络中的某一个。最新tail-off下必须复核方向，不能固定认定204永远是瓶颈。
2. **命令读取之前的背压与提交之后的设备/完成等待，谁在关键路径上占主导。** 历史两者均长，可能是同一依赖链的上下游，不能相加。现有大多数干预只瞄准后者的一小部分。
3. **入站数据有效之后的接收转发/输出，以及首事件之前的未覆盖部分。** 历史余量增加约169 μs，但没有匹配Receiver结束记录；不能因为未测就宣布已排除。
4. **R→A的约351 μs。** 确实存在，但无同口径RDMA对照、无整体占比，当前降为后续分支，不先假定它最大。

绑核、基础单对服务时间、普通CPU提交函数、单纯CQE数量、缩窗、同批交替排列，目前证据不足以作为主要突破口。共享端口错误计数未增长，不证明没有拥塞或信用等待；纯网络服务时间也尚未被单独测出。

## 6. 下一轮只补一组“优化后大区间”的两端匹配数据

目的：先把最新剩余差距定位到发布前、发布后读取前、提交后推进、接收可见后四个候选区间之一。它们属于并行流水线，只报告同角色/同通道区间及与结束的关系，不承诺相加组成完整关键路径。

- 使用同一提交的稀疏boundaries profile，URMA固定202全开、204 tail-off；verbs沿用其原生语义。两后端分别在可用内核运行，不要求立即切核。
- 每后端两端各构建一次，128只做新增路径门禁。4096正式只运行paced → trace → post三项。每点5预热、10采样丢首值后9条。不追加全开fence矩阵。
- 复用0/1/3/4/10/11点，确定首批、第6块及末块GPU就绪/发布；CPU原有链确定读取、提交、CQE、回收；5/6/7/2/8/9点覆盖接收检查、最后有效、转发和输出。
- 本轮不开R返回值和CQ owner专项，保留原生产提交/回收、window8、WRITE RELAX、FADD STRONG。FP8及Combine是现有harness的控制项，不扩展新的调优点，主判断限定BF16。
- 首先核对无探针整体差距及慢端方向。再看同窗包络和各通道，不能因某个请求P95最大就直接判成关键路径；最后结束的通道、阻塞对象及后续推进必须有记录支撑。
- trace扰动、前后漂移、CV先按原5%门槛筛查。对于小于该量级的阶段差异还需结合实际变化和时钟间隙，不把“通过5%”当作微秒精度。失败不原样重跑，先审查原始文件。

| 结果 | 后续只选一个方向 |
| --- | --- |
| 末块命令已发布、尚未读出占主导，且回收卡住 | 分清具体占用者及解除后下一WRITE是否提前，再选单一回收/完成策略干预 |
| 命令及时提交，数据/通知推进及完成长尾占主导 | 进入设备/顺序/完成分支；此时才优先CQE可读观测或同负载verbs depth12 |
| tail已见但payload epoch等得久 | 核查写入可见性、地址/长度和接收内存路径，不先改本端CQ消费 |
| 最后数据已有效，Forwarder/Receiver结束仍明显落后 | 聚焦接收转发、反馈、输出及GPU调度 |
| 四类覆盖都不足以解释API差异 | 补API前后未覆盖边界/启动与结束，禁止把未覆盖余量归给FADD |

确定候选后，才安排对应单变量A/B/B/A并同时看正确性、无打点完整API和局部区间。整体收益必须大于对照波动且反向配对一致。局部指标变好但整体无收益，就停止该优化方向。
