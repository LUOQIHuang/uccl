## 300 μs 落在哪个区间

深度 4 下，两个方向中位间隔最长的位置都在队列 0 的第二对（全局 `pair_index=3`）。其完成间隔的大部分位于其他 WRITE 的完成记录尚未全部取得时。

| 该位置的完成观测区间 | 202→204 中位 μs | 204→202 中位 μs |
| --- | ---: | ---: |
| 该 WRITE 完成 → 同队列最后 WRITE 完成 | 196.760 | 186.970 |
| 同队列最后 WRITE 完成 → 全部队列最后 WRITE 完成 | 110.850 | 105.030 |
| 全部队列最后 WRITE 完成 → 该 FADD 完成 | 4.435 | 2.500 |
| 该 WRITE 完成 → 该 FADD 完成 | 312.080 | 294.410 |

各行分别取中位数，应按单样本计算可加的段长。接近该位置中位数的一个实测样本是 202 第 1 轮 `index=19`。从首次提交开始依次为 98.64 μs（该 WRITE）、295.72 μs（同队列最后 WRITE）、406.55 μs（所有队列最后 WRITE）、410.72 μs（该 FADD）。312.08 μs 中，有 307.91 μs 处于尚未取得全部 WRITE 完成记录的时间段。

对该请求位置的 300 个迭代逐样本拆开再汇总。202→204 的间隔约 62.9% 位于同队列最后 WRITE 完成观测前，35.6% 位于同队列到全队列最后 WRITE 完成观测之间，1.4% 位于全队列最后 WRITE 完成观测后。204→202 对应 63.6%、35.5%、0.8%。这些是时间重叠比例，无法直接给出队列竞争、设备执行或完成上报各自的因果贡献。[逐对记录](summary_urma/pairs.csv) · [按位置统计](summary_urma/positions.csv)

另一个信号是首个 FADD 完成的观测时刻。以第一次提交为起点，202→204 从 58.62 升至 299.91 μs，204→202 从 56.05 升至 284.29 μs。整批最后完成时间同时缩短。完整 Normal 的接收 GPU 依据远端 tail 和数据状态推进，本轮的发送端 CQE 时间和事后数据校验只覆盖本端观测及最终正确性。要判定这段通知延后是否拖慢消费，需要结合完整 Normal 的接收端时序。

## 对 Normal 回退的判断

- 三队列、单线程增加批内请求深度，已经足以把 URMA 的 W→A 观测间隔从 0 放大到约 300 μs 长尾。原 Proxy 循环并非出现这一量级间隔的必要条件。
- 完整 Normal 的两个参考中位数约 683 和 427 μs。本轮深度 4 的整体中位数约 108 和 100 μs，7200 对均低于 400 μs。现有结果复现了部分量级，完整 Normal 的典型等待和 Dispatch 回退仍需单独解释。
- 截至提交 `6668eabc`，同工作量 verbs depth12 结果尚未上传。已有 verbs 串行约 2 μs、完整 Normal 约 0–4 μs，适用于各自负载。下一次 RDMA 窗口按已有配方补三队列，仅需同样两种深度、双向三轮，用来区分这个现象是否也出现在 verbs 的同工作量负载下。若 URMA 窗口还有余量，已有完整 Normal 密集轮询采集可以核对原子返回值在本端可读后，完成记录是否仍明显推迟。[RDMA 深度对照步骤](../../DEPTH12_VERBS.zh-CN.md) · [完整 Normal 密集采集](../../../fadd_path/DENSE.zh-CN.md)
